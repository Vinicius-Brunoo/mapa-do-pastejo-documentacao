Visão geral

O Pastejo Rotacionado é um sistema acadêmico de gestão rural. Ele cadastra pastos, piquetes e animais e registra em qual piquete cada animal foi alocado.

As partes do sistema

NAVEGADOR

       │ fetch, JSON e JWT
       ▼
API EXPRESS · localhost:40003 · dw3backend/
  Router → AutenticaJWT → Controller → Model
       │ SQL parametrizado
       ▼
POSTGRESQL · dw3_pastejo

SERVIDOR DO FRONT · localhost:40103 · dw3frontend/
  Rotas Express → templates .njk → navegador

Em aula O front nunca acessa o banco diretamente. Ele chama a API, que consulta o PostgreSQL e devolve JSON.

Organização MVC

  1. View: templates em dw3frontend/views e scripts em dw3frontend/public/js.
  2. Controller: recebe a requisição, chama o model e devolve a resposta.
  3. Model: executa as consultas SQL e retorna os registros.
  4. Router: associa cada URL ao controller e aplica a proteção JWT.

Banco

No PostgreSQL, quatro tabelas representam a gestão do pastejo. A tabela usuarios atende ao login e não entra na contagem.

Tabelas e relacionamentos

Um pasto possui vários piquetes. A tabela alocado relaciona um animal a um piquete durante um período.

pasto  1 ─── N  piquete  1 ─── N  alocado  N ─── 1  animal

Em aula Mostre a chave estrangeira pastoidfk e explique os tipos texto, decimal, data e booleano.

Usuário acadêmico

A base cria uma conta simples para a apresentação. Não há extensão, criptografia ou hash de senha.

Exclusão lógica

Excluir não apaga a linha. O model troca removido para true, e as consultas retornam somente os registros com removido = false.

UPDATE pasto SET removido = true WHERE pastoid = $1;
SELECT * FROM pasto WHERE removido = false;

Back-end

A API escuta na porta 40003. O código foi mantido simples: router, controller, model e autenticação JWT.

Servidor Express

O CORS permite chamadas do navegador entre as portas 40103 e 40003. O express.json() interpreta o corpo JSON.

Em aula Não existe middleware global de tratamento de erros. O trabalho demonstra apenas o fluxo correto das operações.

Login e JWT

O login compara diretamente a senha informada com a senha acadêmica do banco. Quando coincide, cria um JWT válido por dez minutos.

if (req.body.password === credencial[0].password) {
    const token = jwt.sign({ username }, process.env.SECRET_API,
        { expiresIn: 600 });
    return res.json({ auth: true, token: token });
}

Front-end

O front roda na porta 40103. As rotas Express renderizam templates Nunjucks, e o JavaScript das telas chama a API com fetch.

Estrutura

dw3frontend/
├── routes/              rotas das páginas
├── views/               templates .njk
├── public/js/           funções que chamam a API
├── public/stylesheets/  aparência do sistema
└── app.js               servidor do front

Uma função para cada operação

Cada módulo possui listagem e formulário. O formulário decide se fará inserção, alteração ou exclusão.

  1. A lista chama getAll....
  2. A edição chama get...ByID para preencher os campos.
  3. O botão salvar chama insert... ou update....
  4. O botão excluir chama delete....

Token no navegador

Depois do login, o token é salvo no localStorage. As funções adicionam o token ao cabeçalho das requisições.

localStorage.setItem('token', token);
headers.Authorization = 'Bearer ' + token;

Conexões

Exemplo completo de uma atualização de pasto, desde o formulário até o PostgreSQL.

Fluxo do PUT

  1. O usuário abre o formulário de um pasto.
  2. O JavaScript lê descricao e areatotal.
  3. O navegador envia PUT /updatePasto/1 com JSON e JWT.
  4. O router valida o token e chama UpdatePasto.
  5. O controller lê ID e corpo e chama o model.
  6. O model executa o UPDATE no PostgreSQL.
  7. A API devolve { status: "ok", linhasAfetadas: 1 }.

Docker

O Docker Compose sobe banco, back-end e front-end. Os dois servidores Node usam portas diferentes.

Serviços

ServiçoFunçãoPorta
bancoPostgreSQL e volume dos dadosinterna 5432
backendAPI Express40003
frontendPáginas Express + Nunjucks40103

Executar

cp .env.example .env
docker compose up --build -d
docker compose ps

Front: http://localhost:40103
API:   http://localhost:40003

Para parar:
docker compose down

Em aula O SQL é executado quando o volume do PostgreSQL é criado pela primeira vez.

Demonstração

Roteiro simples para apresentar o sistema funcionando.

O que mostrar

  1. Docker: executar docker compose ps e mostrar os três serviços.
  2. Login: entrar com admin / admin e mostrar o JWT no navegador.
  3. Pasto: cadastrar e editar um pasto.
  4. Piquete: cadastrar um piquete ligado ao pasto.

Plano B

Se a interface tiver algum problema durante a apresentação, use dw3backend/tests/testPastejo.rest no REST Client. Execute primeiro o login para obter o token.

Limitações

O projeto foi mantido propositalmente simples para a disciplina.

Senha acadêmica
admin / admin fica em texto simples. Serve somente à demonstração local.
Tratamento de erros
Não existe middleware próprio. O trabalho considera o caminho de uso correto.
Validações
Os controllers não possuem validações avançadas. Os formulários enviam os campos esperados.
Exclusão
Os registros não são apagados fisicamente; recebem removido = true.
JWT
O token expira em dez minutos. O logout remove o token no navegador.
Ambiente
Os endereços localhost são adequados para executar e apresentar no próprio computador.
